# v0.5.1 변경 및 검증 — 2026-11-18

## 변경

- 실제 VSS 내용을 기준으로 제한된 복구 카탈로그를 생성합니다. 재분석/복구는 사건 이전 시각과 기본 2시간 이내의 스냅샷 신선도를 확인합니다.
- 선택 실패도 기존 UI 실패 안내로 전달합니다. 복구 성공이나 복원 파일 수를 만들지 않습니다.
- 독립 라벨 JEV 평가 도구를 추가했습니다. 중복 요청, 개발/홀드아웃 그룹 누수와 모델 혼합을 거부하며 보정 완료로 판정하지 않습니다.
- 확인된 자체 생성 VSS만 정리합니다. 기본 최대12개, 24시간, 최신2개 보존, 공유 VSS 사용/할당 공간4GiB, 생성 여유512MiB, 최소 디스크 여유2GiB입니다.
- 미해결 사건/검토/복구의 스냅샷은 보호하며 실패·충돌·재시작 뒤에도 durable pin과 삭제 journal을 유지합니다. 복구와 정리는 같은 Windows mutex를 사용합니다.
- 기존 시간당 생성에 보관 사전검사를 연결하고 5분 정리 작업을 제공합니다. 보호 상태가 없거나 손상되면 정리/생성을 중단합니다.
- 해당 venv의 설치 모듈이 구버전으로 남아 예약 작업이 실패하는 문제를 오프라인 패키지 재설치로 해결했습니다. 버전, 모듈 경로, 예약 시각에 대응하는 DB 결과를 확인합니다.

## 실제 VM 검증

- 호스트/게스트 Python 각368개, UI37개 통과. UI lint/TypeScript/프로덕션 빌드 통과.
- 이전 안정화에서 실제 VSS 파일30/30개 해시 복구(삭제 파일1개 포함); 이번에는 복구 중 active pin과 정리 잠금을 확인하고 시험 파일1개를 실제 VSS에서 해시 검증 복구했습니다.
- 정리 직전6개 중 허용된 자체 생성본2개 삭제, 보호본4개 유지. 반복 정리는 추가 삭제0개입니다. 초기 조사 후 정리 전 이미 없어진 복사본은 우리 삭제로 계산하지 않습니다.
- 남은 보호본으로 공유 사용 공간 약5.45GiB/할당 약5.90GiB가 4GiB 예산을 초과했습니다. **용량 목표 달성으로 주장하지 않으며 새 생성을 보류합니다.** 검토 hold6건을 임의 해제하지 않았습니다.
- Windows VSS 전체 quota를 변경하지 않았습니다. 외부 Windows/provider 동작의 축출이나 COW 증가까지 앱이 보장할 수는 없습니다.
- 수집기 PID를 유지한 인계 및 이번 정리/복구에서 추가 이벤트 유실0/큐 비움0. 누적 유실102267, 큐 비움0을 보존했습니다.
- 이전 UI 최종 연속 구간600.828초: 원본103450건, 추가 유실0/큐 비움0/임시 etilqs 쓰기0. UI 저장 지연 .700/.982/1.005초.
- JEV 전용 네트워크 정책, 사용자 계정 설정, UI asar와 기존 기록을 유지했습니다. 이번 시험에서 JEV 데이터를 새로 전송하지 않았습니다.

## 함께 사용하는 UI 안정화

동일 통합 브랜치에서 실시간 캐시/표본을 제한하고 일반 이벤트 차트를 SQLite로 집계합니다. 실제 대응 증거/중복 제거 및 과거 페이지를 유지합니다.
SQLite 정렬 임시파일이 커널 이벤트로 되먹임되던 회귀를 temp_store=MEMORY 검증으로 수정했습니다. 중간 회귀/롤백 유실50388건을 숨기지 않았고 기존51879 + 50388 = 102267입니다. 최종 구간 추가0을 전체 유실0으로 해석하면 안 됩니다.
화면 디자인/CSS/기존 기능/기록 DB 스키마는 유지했습니다. 캐시 상한은 실시간 창의 제한이며 같은 timestamp 묶음과 명시적 과거 조회는 예외입니다.

## 남은 배포/평가 범위

대표 라벨 자료가 없으므로 JEV 오탐·미탐 보정은 미완료입니다. 무해한 정상 작업3종은 실제 jev-1.14.0의 .22/.25/.18 점수를 받았지만 대표 통계가 아닙니다.
현재 자동 대응은 기존 승인된12개 시험 파일 범위이며 전체 PC 복구가 아닙니다. 운영 보호 폴더/manifest, 검토 hold 해소, 통합 설치/다른 PC 최초 설치/서명 배포, 장시간 및 저사양 성능 평가는 별도입니다.

## 종료 전 추가 관찰 — 위 검증 구간과 구분

게시 후 실행 중인 DB들에 전체 quick_check와 passive WAL checkpoint를 수행한 구간에서 유실이 추가843건 증가하여 누적103110건이 됐습니다. 큐 비움은0이며 카운터를 초기화하지 않았습니다. DB 네 개의 무결성 검사는 모두 ok였지만 이를 이벤트 수집 무손실로 해석하지 않습니다.
이 온라인 점검과 저장소 경합이 연관됐을 가능성이 있으나 원인은 확정하지 않았습니다. 이후 종료 절차에서는 활성 수집 중의 전체 DB 검사/수동 WAL 체크포인트를 제거하고 기존 WAL과 최신 상태 기록을 보존합니다. 운영 중 무거운 무결성 점검의 영향은 남은 검증 항목입니다.
