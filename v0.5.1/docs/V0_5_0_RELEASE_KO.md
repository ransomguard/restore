# restore/JEV v0.5.0 — 2026-11-18

## v0.4.0 이후 변경

- Track A PID+생성 FILETIME, parent==creator, 신호 수명/유실 및 실제 종료 전 재검증.
- Track B 실제 JEV 전송과 승인된 유한 복구 범위; JEV/VSS 대기를 수집기에서 분리한 영속 비동기 응답 작업.
- 사건 세대별 중복 대응 차단, 중단된 응답 자동 재실행 금지 및 review hold 보존.
- 배치 원본 수집/DB 저장, 완료 원본 capacity 슬롯 반환, 보호 중인 증거를 건너뛰는 제한된 정리 cursor.
- resident 수집기 준비 handshake/작업자 인계, 드라이버 교체 전 drain과 중단 구간 기록, 재부팅 이후 상태 복귀.
- UI 실제 저장 ACK 이후 전달 완료, 64항목/64KiB 협상과 구버전 20항목 fallback. 기존 durable ID 유지.
- 중요한 이벤트의 판단 근거와 실제 결과를 UI에 전달; 시험 결과는 시험으로 표시하고 정상 프로세스 종료를 강제 종료 수치에서 제외.
- 새 PC의 경로를 지정하는 `deployment/configure.py`, 통합 실행 안내, 구성요소 커밋 고정 manifest.
  기존 VM 전용 실행 경로는 배포용 시작 도구에서 제거. 기본 관측/시험 표시와 명시적 live 승인 요구는 유지.

## 기존 VM에서 확보한 증거

이 항목은 11/17 완료 검증 기록의 요약입니다. 이번 업로드 과정에서 악성코드나 부하 시험을 다시 돌린 것은 아닙니다.

- Python 319개, UI 28개 테스트; UI lint/타입 검사/Windows 설치 파일 빌드 통과.
- 30개 파일, 총 120,000 write 호출(400/800/1200회/초), 120,750 커널 시도, 30개 감사 구간 순서 확인.
  추가 dropped/flushed 0. 역사적 유실 51,879는 초기화하지 않음. write 호출 수는 프로세스 개수가 아님.
- Track B: 실제 JEV `jev-1.14.0` 점수 0.86 → 같은 프로세스 세대 종료 확인 → 승인된 12개 파일 VSS 해시 복구 → UI 2/2 ACK.
  별도 0.58 결과는 검토로 보류했고 악성으로 강제 조정하지 않음.
- Track A: 무해한 where.exe 복사본을 vssadmin.exe로 사용한 자식 생성 차단 → 부모 종료 확인 → 12개 파일 VSS 복구 → UI 2/2 ACK. JEV 호출 없음.
- 응답 중 수집 지속, 두 번째 cold reboot 자동 복귀. OS/드라이버 중단 구간은 coverage gap으로 남김.
- UI 저장 지연: 앞선 60.84초 표본에서 수정 후 3.561/3.290/1.797초 표본. 모든 상황의 지연 상한 보장은 아님.
- 기존 UI 기록/검토 hold 유지. 직접 Python 인터넷 통신은 차단, 실제 JEV 브리지 예외만 허용하는 VM 정책 확인.

## 이번 배포의 별도 검증/한계

새 경로 설정 도구는 공간 포함 경로, 검사 전용 무변경, 반복 실행, 기존 DB/설정/실행 파일 보호를 테스트합니다.
이번 배포 검증 결과는 `deployment/RELEASE_VALIDATION.json`에 기록합니다.
경로 이식용 런처와 새 예약 작업 템플릿은 다른 PC 첫 설치/새 v0.9.0 서명 드라이버까지 VM 재검증된 설치 패키지는 아닙니다.

대표 데이터에서 JEV 임계값 보정, 임의 피해 파일의 완전한 manifest 생성, 일반 사용자 제품 배포/서명,
장시간 안정성·자원 최적화는 여전히 남아 있습니다. 검증은 무해한 시험 입력과 승인된 파일 범위에 한정됩니다.
키·서명 인증서 개인 키·VM 이미지·사용자 DB·개별 환경의 VSS ID는 포함하지 않습니다.
